# W2-16 open questions

Decisions taken while building speakers v2 (audio-002..006, audio-009, api-013, db-011).

## 1. `/speakers/search` defaults

- **Question:** the spec marks the defaults for a missing `limit`/`offset` as inferred, and the base
  had no limit at all.
- **Decision:** `limit` 100, `offset` 0, `include_samples` true. `DatabaseManager::search_speakers`
  (no paging) stays for internal callers and returns every match.
- **Reason:** follows the spec's recommendation. Because a call without parameters now returns at
  most 100 names, every app caller was updated with the change: the speakers settings page pages
  with `offset` (`lib/speaker-search.ts`, 100 per page, until a short page, a page with no new id,
  or 100 pages), the chat @-mention suggestions send `limit=50&include_samples=false`, and the
  search window's people filter sends `limit=5` (or `20` after `@`) with `include_samples=false`,
  matching what each one displays. The voice-training name suggestions keep the plain call; a
  name prefix rarely matches 100 people.

## 2. Name prefix matching

- **Question:** the base built the pattern as `? || '%'`, so a `%` or `_` typed by the user acted as a
  wildcard, and SQLite cannot use an index for an expression pattern.
- **Decision:** the prefix is escaped (`\`, `%`, `_`) and bound as one pattern with `ESCAPE '\'`.
  Matching stays case-insensitive (SQLite's default `LIKE`), ordering is `name COLLATE NOCASE`, and
  rows that share an exact name still collapse to the lowest id. Both the light and the sampled
  query page inside the grouped name list.
- **Reason:** literal prefixes are what an autocomplete box means; the bound pattern keeps the
  `idx_speakers_hallucination_name` path open.

## 3. Sample route limits and status codes

- **Question:** the spec infers the maximum clip length and the exact status for each error.
- **Decision:** clips are at most 120 s. Missing, non-finite or negative `start`/`end`, `end <=
  start` and over-long clips are 400; an unknown chunk is 404 with `audio chunk not found`; an empty
  or `.` path, a `cloud://` path, a file missing on disk and a window outside the decoded audio are
  422; database and decode failures are 500. `end` may run up to 1 s past the end of the audio and
  is clamped; `start` at or beyond the end is 422. Errors are JSON `{"error": ...}`.
- **Reason:** the UI caps previews at 3 s but other callers pass whole segment durations, so the cap
  is generous. Segment end times overshoot the encoded audio slightly, hence the tolerance.

## 4. Sample decoding and encoding

- **Question:** which decoder and output format.
- **Decision:** only the requested window is decoded: `start` to `end` plus 50 ms, so decoder
  rounding never shortens the clip. ffmpeg runs with `-ss <start> -t <length>` before `-i` and
  returns 16 kHz mono (`read_audio_window_from_file`); when ffmpeg is missing or fails, the built-in
  symphonia decoder (`pcm_decode_window`, first channel, native rate) seeks to `start` when the
  container allows it and otherwise decodes from the beginning, keeping only the window. Both
  decoders succeed with an empty buffer for a window past the end of the file and fail for a file
  they cannot read, which is how the route tells "outside the chunk" (422) apart from a decode
  failure (500). A buffer that ends more than 1 s before `end` is also 422; a shorter shortfall is
  clamped. The clip is trimmed to `end` and returned as mono 16-bit PCM WAV. The route sits in the
  non-OpenAPI router next to `/audio/metrics` and uses the existing auth middleware, so the UI
  passes the key as `?token=` (an `<audio>` element cannot send headers).
- **Reason:** batch chunks can be long and callers may pass whole segment durations, so decoding
  the full file for every preview would waste time and memory; the window keeps the work bounded by
  the 120 s cap.

## 5. Reassign `scope` details

- **Question:** the spec infers the scope semantics around the observed fields.
- **Decision:**
  - A missing `scope` is `auto`; an unknown value is rejected by the JSON extractor.
  - The rename-in-place path (`auto`, current speaker unnamed and not flagged as a
    hallucination, no named speaker with that name) changes only the speaker's name and moves the
    chunk's matching live meeting segments; it runs no similar-voice propagation and never touches
    the `hallucination` flag. A voice flagged as a hallucination takes the chunk path instead, so a
    single relabel cannot turn a whole junk cluster into a named person, and the flag stays set.
    The spec says the rename clears the flag; that is the one point where this build differs, so
    that undo is exact.
  - Undo of a rename-in-place: `/speakers/update` with `previous_speaker_name` restores the name
    (a name that was NULL comes back as `""`; both read as unnamed everywhere), and posting
    `old_segment_assignments` to `/speakers/undo-reassign` puts the meeting segments back. Nothing
    else changed, so the speaker ends up as it was.
  - Undo of the chunk path: `/speakers/undo-reassign` puts every recorded `audio_transcriptions`
    row and meeting segment back on its old speaker. A previous speaker that the reassign deleted
    (no references left) is re-created as a nameless row with the same id; its old name,
    hallucination flag and the embedding that moved with the chunk are not restored.
  - The target lookup trims and compares case-insensitively; the response's `new_speaker_name` is
    the stored name of the speaker that received the chunk (an input of `alice` that lands on
    `Alice` reports `Alice`).
  - The chunk's current speaker is its first row that has one. A chunk whose rows have no speaker
    takes the chunk path; its rows are recorded with `old_speaker_id: 0`, and undo turns `0` back
    into NULL instead of creating a speaker with id 0.
  - When the target is the chunk's own speaker, no embedding moves (the base reported 1).
  - On the chunk path, rows of speakers absorbed by propagation are recorded too:
    `audio_transcriptions` rows in `old_assignments`, live meeting segments in
    `old_segment_assignments`. Diarization rows, identity evidence and embeddings of absorbed
    speakers are not restored by undo (the base did not restore embeddings either).
  - Live meeting segments follow the chunk when their text equals one of the chunk's transcriptions
    and `captured_at` is within 2 s of it.
- **Reason:** keeps every undo path complete for what the UI can see, and avoids inventing ids.

## 6. Which deletions are guarded

- **Question:** audio-004 says `/speakers/delete` is unchanged, while db-011 says the target refuses
  to delete a speaker that still has rows.
- **Decision:** the reference guard (delete the `speakers` row only when none of the five tables
  points at it, otherwise keep it and log the table) applies to merge, propagation absorb, and the
  reassign cleanup of the chunk's previous speaker. The base deleted that previous speaker as soon
  as it had no embeddings, even when other chunks still pointed at it; that was the orphan source
  the 20260812120000 migration repairs. `/speakers/delete` keeps the base behaviour (delete the
  transcriptions, embeddings, orphaned chunks and the speaker) and now also unlinks live meeting
  segments and diarization segments (`speaker_id = NULL`) and deletes identity evidence, so no
  orphan ids are left behind. Merging a speaker into itself is a no-op (the base deleted it), and
  merging into a missing speaker fails with 404 before anything moves.
- **Reason:** "delete" is an explicit user action whose base semantics clients rely on; every other
  path is automatic and must never orphan references.

## 7. Automatic self-naming thresholds (audio-009)

- **Question:** the lookback window and the minimum chunk count are inferred.
- **Decision:** 24 h lookback and at least 3 distinct chunks (the base `MIN_TRANSCRIPTION_COUNT`),
  replacing the base's 10 transcription rows. Evidence rows must last at least 2 s, not come from the
  `live` engine and fall outside every meeting (an open meeting counts as running until now). The
  window must hold exactly one distinct input speaker of any kind, and "never heard on output" looks
  at all time, not only the window.
- **Reason:** follows the spec and its verification note (one distinct speaker of any kind, named or
  not). Checking output history over all time is the stricter reading.

## 8. Speaker table self-heal

- **Question:** what the startup self-heal touches.
- **Decision:** after migrations, `ensure_speaker_tables` recreates `speakers` or
  `speaker_embeddings` only when the table is missing, together with its lookup index
  (`idx_speakers_hallucination_name`, `idx_speaker_embeddings_speaker_id`). Existing tables are not
  altered. It is public so tests (and a future repair command) can call it.
- **Reason:** db-011 describes creation of missing tables only; altering existing tables belongs to
  migrations.

## 9. Seams for W2-17 (stream-scoped live speakers)

- **Question:** what W2-17 can build on.
- **Decision / notes:**
  - `DatabaseManager::SPEAKER_REFERENCE_TABLES` and the private absorb helpers
    (`repoint_speaker_references`, `delete_speaker_row_if_unreferenced`, `absorb_speaker_in_tx`) are
    the single place that knows the five tables; reuse them for any new merge or backfill path.
  - `move_chunk_meeting_segments` is the only reassign code that matches live segments (exact text,
    2 s window). Once segments carry `stream_id`/`session_speaker_id`, W2-17 may want a reassign to
    also move the other segments of the same `(meeting_id, stream_id, session_speaker_id)`; that
    belongs in this helper, and the moved rows must keep landing in `old_segment_assignments`.
  - The self-naming query skips `transcription_engine = 'live'` rows already, matching how
    audio-008 marks live mirrors.

## 10. Reassign from the UI

- **Question:** audio-006 lists the speaker-assign popover and the timeline bulk relabel as callers,
  but the plan's owner paths only name the speakers settings page. Without changes, both would
  silently switch to the new `auto` default.
- **Decision:** both are updated (small edits outside the listed owner paths). The popover keeps the
  base's two steps for responsiveness: first `propagate_similar: false, scope: "auto"` (instant;
  may rename the whole voice), then, only when no whole-voice rename happened,
  `propagate_similar: true, scope: "chunk"` in the background. Its undo renames the voice back
  through `/speakers/update` when `previous_speaker_name` is set and posts the moved rows of both
  steps to `/speakers/undo-reassign`, propagation rows first so the original assignment wins. The
  timeline bulk relabel sends `scope: "chunk"` for every selected chunk, and its popover runs with
  `scope="chunk"` and no propagation. The popover's name search uses
  `limit=20&include_samples=false`, since it never shows samples. The other search callers are
  covered under question 1.
- **Reason:** keeps bulk relabel chunk-exact as before and gives single relabels the v2 behaviour
  with a complete undo.
