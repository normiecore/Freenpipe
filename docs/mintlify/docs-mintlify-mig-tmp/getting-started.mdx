Freenpipe has no release yet, so you build it from source. Windows (x86_64) is the primary platform; the macOS and Linux code paths are kept compiling but are not exercised in this fork.

## desktop app or CLI?

| choose | if you want |
| --- | --- |
| desktop app | visual timeline, pipes, connections, chat, settings, and guided permissions |
| CLI | local recording, REST API access, and terminal-first workflows |

## build from source

you need Rust (the version is pinned in `rust-toolchain.toml`), [bun](https://bun.sh), and on Windows the Visual Studio 2022 Build Tools with the C++ workload, LLVM and CMake.

```bash
git clone https://github.com/normiecore/Freenpipe
cd Freenpipe
```

the full Windows recipe, including the native sidecars and the desktop app build, is in [docs/dev/windows-build.md](https://github.com/normiecore/Freenpipe/blob/main/docs/dev/windows-build.md). macOS and Linux steps are in [CONTRIBUTING.md](https://github.com/normiecore/Freenpipe/blob/main/CONTRIBUTING.md).

### CLI

the CLI binary is still named `screenpipe`, so existing scripts, pipes and MCP configurations keep working. build and start it:

```bash
cargo build --release -p screenpipe-engine --bin screenpipe
./target/release/screenpipe record
```

this starts recording and serves the API. data is stored in `~/.screenpipe/` on your local machine.

<Warning>Freenpipe uses the same data directory and ports as screenpipe, so it does not run alongside an installed screenpipe. quit one before starting the other.</Warning>

### desktop app

build the app from `apps/screenpipe-app-tauri` as described in the build guide. the app manages recording, settings, search, pipes, and AI connections.

### troubleshooting: `screenpipe record` not working

if the command fails, try these fixes in order:

**Linux: missing system libraries:**
```bash
sudo apt install libasound2-dev ffmpeg  # ubuntu/debian
sudo dnf install alsa-lib ffmpeg         # fedora
```

**Windows: .NET runtime missing:**
if you use the CLI on its own, install [.NET 8.0](https://dotnet.microsoft.com/en-us/download/dotnet/8.0).

**Windows: exits at once with a `libopenblas.dll` error:**
put OpenBLAS on `PATH` first, as described in the build guide.

**port 3030 already in use:**
if Freenpipe or screenpipe is already running, the CLI will fail to bind. check for existing processes:
```bash
lsof -i :3030     # macOS/Linux
netstat -ano | findstr :3030  # Windows
```

still stuck? open a [GitHub issue](https://github.com/normiecore/Freenpipe/issues).

### suppress CLI reminders (optional)

the CLI prints periodic tips while it records. to run it silently, disable them:

```bash
SCREENPIPE_NO_REMINDERS=1 screenpipe record
```

or set it once in your shell:
```bash
export SCREENPIPE_NO_REMINDERS=1
screenpipe record
```

### access your recorded timeline

after starting the CLI, you have three ways to access your screen history:

1. **desktop app**: a visual timeline and built-in search (build it from source, see above)
2. **REST API**: query recorded content directly via curl or code (see below)
3. **AI assistants**: connect Claude, Cursor, or other tools via MCP

## verify it's running

once Freenpipe starts, it serves an API on `localhost:3030`:

```bash
# check health
curl http://localhost:3030/health

# search your screen history
curl "http://localhost:3030/search"
```

## check and update your version

```bash
# check your current version
screenpipe --version
```

to update, pull the latest commits and rebuild:

```bash
git pull
cargo build --release -p screenpipe-engine --bin screenpipe
```

<Note>the `screenpipe` package on npm is published by the upstream vendor, not by Freenpipe. installing it with `npx` or `npm` runs upstream's build, not this one.</Note>

### API authentication (required)

the search endpoint requires an API key. get your key by running:

```bash
screenpipe auth token
```

then use it in curl:

```bash
curl "http://localhost:3030/search?q=example" \
  -H "Authorization: Bearer <your-api-key>"
```

or set it as an environment variable:

```bash
export SCREENPIPE_API_KEY=$(screenpipe auth token)
curl "http://localhost:3030/search?q=example" \
  -H "Authorization: Bearer $SCREENPIPE_API_KEY"
```
