Upstream's team features (shared pipes and recording filters, managed AI presets, admin roles and invites) ran against the vendor's team service and required a vendor account. Handvel does not use the vendor's servers, so those features are not available against them.

## what replaces it

Teams come back as **Handvel Hub**, work package WR-03 (owner decision 5 in [DECISIONS.md](https://github.com/normiecore/Handvel/blob/main/docs/clean-room/DECISIONS.md)):

- a small self-hostable server (single binary or Docker image) that you run for your organisation
- team creation, invite links, admin roles and per-member API tokens
- opt-in sharing policies: members' engines push only what their policy allows, and admins can query only data that members explicitly share, never raw unshared recordings
- the team settings in the app, the `screenpipe team` CLI and the MCP team tools, pointed at your hub URL instead of a vendor host

With no hub configured, team features stay hidden. Progress is tracked in [STATUS.md](https://github.com/normiecore/Handvel/blob/main/docs/clean-room/STATUS.md).

## until then

Pipes are plain `pipe.md` files and recording filters are local settings. To give colleagues the same setup, share the pipe files through your own channels (a git repository, for example) and document the filters you use. See [pipes](/pipes) and [pipe permissions](/pipe-permissions).

questions? open a [GitHub issue](https://github.com/normiecore/Handvel/issues).
