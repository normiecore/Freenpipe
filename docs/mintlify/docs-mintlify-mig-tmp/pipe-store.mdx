a pipe is an AI automation that works on your recorded screen and audio data. each pipe is a single `pipe.md` file in `~/.screenpipe/pipes/<name>/`. see [pipes](/pipes) for the format.

## the pipe store

upstream's pipe store was a catalogue hosted on the vendor's servers. Handvel does not use it, so the store listings from the vendor are not available.

the store comes back as work package WR-01 (owner decision 5 in [DECISIONS.md](https://github.com/normiecore/Handvel/blob/main/docs/clean-room/DECISIONS.md)): a static registry kept in the `registry/` directory of the [Handvel repository](https://github.com/normiecore/Handvel), used by default and replaceable with your own registry URL. installs are checked against a sha256 recorded in the registry. publishing a pipe means opening a pull request that adds its folder to the registry, and CI validates the submission. progress is tracked in [STATUS.md](https://github.com/normiecore/Handvel/blob/main/docs/clean-room/STATUS.md).

until then, use the built-in template pipes below or write your own.

## built-in template pipes

these ship with Handvel and are available without an install:

| pipe | what it does |
|------|-------------|
| **Day Recap** | summarize accomplishments, key moments, unfinished work |
| **Standup Update** | generate a copy-paste standup report |
| **Time Breakdown** | where your time went by app, project, category |
| **AI Habits** | how you use AI tools: patterns and insights |
| **AI Prompt Journal** | collect the prompts you send to AI tools into a markdown journal |
| **Meeting Summary** | summarize meeting transcripts with action items |
| **Export Video Clip** | create a video clip from your screen recordings |

## troubleshooting

### installed pipe not showing in UI

**problem**: a pipe was installed, but it doesn't appear in **settings → pipes**.

**solution**: 

1. restart Handvel (close and reopen the app). the pipe list sometimes takes a few seconds to refresh.
2. check that the pipe folder exists:
   - **macOS/Linux**: `ls ~/.screenpipe/pipes/` and verify the pipe name appears
   - **Windows**: `dir %USERPROFILE%\.screenpipe\pipes\` (or `echo $env:USERPROFILE\.screenpipe\pipes` in PowerShell)
3. if the folder is missing, install the pipe again.
4. verify Handvel API is healthy: `curl http://localhost:3030/health`

### pipes disappearing from UI

**problem**: pipes you installed are suddenly gone, or they appear and then vanish.

**solution**: Handvel uses a **tombstone system** to track deleted pipes and prevent them from being restored. a pipe may be marked as deleted if:
- you deleted it via **settings → pipes → delete**
- you uninstalled the app (rebuilding the pipe list removes orphaned pipes)
- the pipe folder was manually deleted from `~/.screenpipe/pipes/`

**to recover**:
1. go to **settings → pipes** and look for the pipe in the installed list
2. if it's not there, install the pipe again (copy its folder back into `~/.screenpipe/pipes/`)
3. if the pipe is still not showing, the tombstone file (`.tombstones.json`) may need to be cleared. **backup first**, then delete `~/.screenpipe/pipes/.tombstones.json` and restart Handvel

**to prevent**: avoid deleting pipes manually from the filesystem. use the **delete** button in the app instead; it keeps the tombstone records consistent.

### pipe install succeeds but doesn't execute

**problem**: the pipe is installed and enabled, but scheduled runs produce no output or logs.

**solution**: the issue is usually the pipe execution, not the installation. see [debug Handvel pipes](/pipe-debugging) for execution troubleshooting (logs, API health, provider auth).

## create your own pipe

a pipe is just one markdown file. you can create a custom pipe for anything.

### quick way: ask AI to build it

paste this into Claude Code, Cursor, or any AI coding tool:

```text
create a screenpipe pipe that [DESCRIBE WHAT YOU WANT].

a pipe is a single markdown file at ~/.screenpipe/pipes/{name}/pipe.md
with YAML frontmatter (schedule, enabled) and a prompt body.
the AI agent queries http://localhost:3030/search for screen data.
```

### manual way: write it yourself

```bash
mkdir -p ~/.screenpipe/pipes/my-pipe
cat > ~/.screenpipe/pipes/my-pipe/pipe.md << 'EOF'
---
schedule: every 30m
enabled: true
---

Your instructions here. The AI agent will execute this prompt
and can query screenpipe at http://localhost:3030/search.
EOF
```

then install it: go to **settings → pipes** and it will appear in your installed pipes list.

[full pipe development guide →](/pipes)

### sharing a pipe

a pipe is a folder with a `pipe.md` file, so you can share it as a file or through a git repository. once the GitHub-hosted registry (WR-01) lands, you will be able to submit a pipe to it with a pull request.

## what pipes can do

| feature | description |
|---------|-------------|
| **no code** | pipes are plain markdown: describe what you want in natural language |
| **any schedule** | run every 5 minutes, hourly, daily, or on-demand |
| **full API access** | query screen text, audio, browser URLs, app activity, input events |
| **any AI model** | use your own API key, your ChatGPT/Claude subscription, or local Ollama |
| **external APIs** | pipes can call Slack, Toggl, Notion, Gmail or any other service with an API |
| **privacy controls** | restrict what data a pipe can access with [permissions](/pipe-permissions) |
| **shareable** | a pipe is one file, so it can be shared like any other file |

need help building a pipe? open a [GitHub issue](https://github.com/normiecore/Handvel/issues).
