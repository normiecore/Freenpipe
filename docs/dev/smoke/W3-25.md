# W3-25 Windows smoke checks

Entries follow the format in [../windows-smoke-checklist.md](../windows-smoke-checklist.md). Run
them on a W3-25 (or later) build in the isolated dev setup: `FP_DD`, port 3035,
`SCREENPIPE_API_KEY`. The `api` helper is the one from PLAN.md section 4.

### W3-25 Local OpenAI-compatible proxy and BYO web search

- [ ] **SMK-W3-25-1** (Runtime) The local chat proxy streams from a local Ollama preset
  - Setup: release-dev engine build; `source scripts/dev/dev-env.sh smoke`; Ollama for Windows running with a small model pulled (for example `ollama pull llama3.2:1b`). Write `$FP_DD/store.bin` as `{"settings":{"aiPresets":[{"id":"local","provider":"native-ollama","url":"http://localhost:11434/v1","model":"llama3.2:1b","defaultPreset":true,"maxContextChars":200000,"apiKey":null,"prompt":""}]}}`.
  - Steps: 1. Start `screenpipe.exe record --port $FP_PORT --data-dir "$FP_DD"`. 2. `api /v1/local/chat/completions -X POST -N -d '{"messages":[{"role":"user","content":"Say hi in three words"}],"stream":true}'`. 3. Repeat without the `Authorization` header (plain `curl`). 4. Repeat step 2 and press Ctrl+C after the first lines.
  - Expected: step 2 prints `data: {...}` lines as they arrive and ends with `data: [DONE]`; step 3 is a 403; after step 4 the Ollama log (or Task Manager CPU) shows generation stopping within a few seconds.
  - Result:
- [ ] **SMK-W3-25-2** (Runtime) Missing preset and unreachable provider errors
  - Setup: as SMK-W3-25-1, engine running.
  - Steps: 1. Rename `$FP_DD/store.bin` and call `api /v1/local/chat/completions -X POST -d '{"messages":[]}'`. 2. Restore it, quit Ollama, repeat step 1. 3. Search `$FP_DD/engine.log` for the preset's `apiKey` value if you set one.
  - Expected: step 1 is a 400 whose `error.message` says no default AI preset is set up; step 2 is a 502 whose message starts "could not reach the AI provider:"; step 3 finds nothing.
  - Result:
- [ ] **SMK-W3-25-3** (Runtime) Web search is off by default and works against SearXNG
  - Setup: release-dev engine; a SearXNG instance with the JSON format enabled (for example `docker run -p 8888:8080 searxng/searxng` with `search.formats: [html, json]` in its settings.yml), or skip step 3 if none is available.
  - Steps: 1. Start the engine with no `SCREENPIPE_WEB_SEARCH_*` and no AI gateway set. 2. `api /v1/web-search -X POST -d '{"query":"rust language"}'`. 3. Restart the engine with `SCREENPIPE_WEB_SEARCH_URL=http://127.0.0.1:8888` and repeat step 2.
  - Expected: step 2 is a 501 with `"error":"web_search_not_configured"`; step 3 is a 200 with a numbered `content` list and up to 5 `sources` with http(s) URLs.
  - Result:
- [ ] **SMK-W3-25-4** (UI smoke) Chat offers `sp_web_search` only when search is configured
  - Setup: `scripts/dev/app-dev.sh` with the installed screenpipe quit; any working chat preset (Ollama is fine).
  - Steps: 1. Start the app without `SCREENPIPE_WEB_SEARCH_URL`, open a chat and ask "search the web for the latest Rust release". 2. Quit, start the app with `SCREENPIPE_WEB_SEARCH_URL` pointing at the SearXNG from SMK-W3-25-3, open a new chat and ask the same.
  - Expected: in step 1 no web-search tool runs (the agent says it cannot search the web); in step 2 an `sp_web_search` tool call appears, its result lists sources, and the message shows web source chips.
