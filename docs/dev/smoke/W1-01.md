# W1-01 Windows smoke checks

Entries follow the format in [../windows-smoke-checklist.md](../windows-smoke-checklist.md). Run
them on a W1-01 (or later) build in the isolated dev setup: `FP_DD`, port 3035,
`SCREENPIPE_API_KEY`.

### W1-01 Schema v2.7.104: 28 migrations and ocr_text retirement

- [ ] **SMK-W1-01-1** (Runtime) A fresh recording stores OCR on frames and search reports an empty OCR engine
  - Setup: release-dev engine build; `source scripts/dev/dev-env.sh smoke` with a new, empty `FP_DD`.
  - Steps: 1. Start `screenpipe.exe record --port $FP_PORT --data-dir "$FP_DD"`. 2. For two minutes, use an app that forces the OCR fallback (a terminal such as Windows Terminal, or a game) plus a normal app. 3. `api '/search?content_type=ocr&limit=5'`. 4. `sqlq "select name from sqlite_master where name like 'ocr_text%'"`. 5. `sqlq "select count(*) from frames where text_json is not null"`. 6. `sqlq "select count(*) from _sqlx_migrations"`.
  - Expected: step 3 returns items whose `ocr_engine` is `""`; step 4 prints nothing; step 5 is greater than 0 once OCR has run; step 6 is 117. `engine.log` shows no migration error.
  - Result:
- [ ] **SMK-W1-01-2** (Runtime) A data dir created by the base schema upgrades in place
  - Setup: a data dir recorded with a pre-W1-01 build (for example the v2.5.28-alpha.1 engine, or any build from `c5489be`) that has captured OCR frames, e.g. 5 minutes with a terminal open. Never use `~/.screenpipe` itself.
  - Steps: 1. Stop the old engine. 2. Start the W1-01 engine on the same `FP_DD`. 3. Read the first lines of `engine.log`. 4. Search for a word you saw in the terminal: `api '/search?q=<word>&content_type=ocr&limit=5'`. 5. `sqlq "select count(*) from frames where text_json is not null"`.
  - Expected: the log carries the notice about moving OCR text off the retired ocr_text table before migrations run, then starts normally; step 4 finds the old frames with an empty `ocr_engine`; step 5 is greater than 0; the timeline still shows the old frames with their text.
  - Result:
- [ ] **SMK-W1-01-3** (Manual) A copy of a screenpipe v2.7.104 database opens without migration repairs
  - Setup: the installed screenpipe v2.7.104 quit. Copy `~/.screenpipe/db.sqlite` (plus `-wal`/`-shm` if present) into a new scratch `FP_DD`; work only on the copy, and delete it afterwards. Skip this entry if you do not want to copy real data.
  - Steps: 1. `sqlq "select version, hex(checksum) from _sqlx_migrations where version >= 20260601000000"` and keep the output. 2. Start the W1-01 engine on the scratch `FP_DD`. 3. Read `engine.log`. 4. Repeat step 1.
  - Expected: no "previously applied but has been modified" warning and no migration error in the log; step 4 prints exactly what step 1 printed (nothing re-applied or rewritten); search and timeline return the copied data.
