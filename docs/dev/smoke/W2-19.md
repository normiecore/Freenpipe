# W2-19 Windows smoke checks

Entries follow the format in [../windows-smoke-checklist.md](../windows-smoke-checklist.md). Run
them on a W2-19 (or later) build in the isolated dev setup: `FP_DD`, port 3035,
`SCREENPIPE_API_KEY`. The GPU entries need a machine with a DirectX 12 GPU whose driver installs
the Vulkan runtime (any recent NVIDIA, AMD or Intel driver). Section 5.1 of
[../windows-build.md](../windows-build.md) explains the features, files and log lines.

### W2-19 GPU runtimes and bundled models: Vulkan whisper, DirectML, install layout

- [ ] **SMK-W2-19-1** (Manual) A release-dev build with the `vulkan` and `directml` features succeeds
  - Setup: LunarG Vulkan SDK 1.4.313.0 installed with its defaults; a new Git Bash with `source scripts/dev/msvc-env.sh`; `echo $VULKAN_SDK` prints the SDK folder.
  - Steps: 1. `glslc --version`. 2. `cargo build --profile release-dev -p screenpipe-engine --bin screenpipe --features vulkan,directml`. 3. `cd apps/screenpipe-app-tauri/src-tauri && cargo build --profile release-dev --features vulkan,directml` (after `bun run build`, or with a placeholder `../out/index.html`).
  - Expected: both builds finish; the whisper-rs-sys build output mentions ggml-vulkan / its shader generator and no "Please install Vulkan SDK" panic. Note the build times in the result.
  - Result:
- [ ] **SMK-W2-19-2** (Hardware) Whisper transcribes on Vulkan and logs it
  - Setup: the engine from SMK-W2-19-1; `source scripts/dev/dev-env.sh smoke`; ONNX Runtime and OpenBLAS DLLs on `PATH` as in windows-build.md section 4; a whisper engine selected (`--audio-transcription-engine whisper-large-v3-turbo-quantized`, or `whisper-tiny` for a quicker run); a wav fixture with speech (record 20 seconds of yourself reading a paragraph, 16 kHz mono).
  - Steps: 1. Start `target/release-dev/screenpipe.exe record --port $FP_PORT --data-dir "$FP_DD" --disable-vision > "$FP_DD/engine.log" 2>&1 &`. 2. Play the fixture through the speakers (or speak) for 20 seconds. 3. `grep -n "whisper context" "$FP_DD/engine.log"`. 4. `api '/search?content_type=audio&limit=5'`.
  - Expected: step 3 shows `whisper context: GPU backend Vulkan (windows build asks for Vulkan) on Vulkan0 (<GPU name>)`; step 4 returns the spoken text. Task Manager shows GPU "Compute" activity while it transcribes.
  - Result:
- [ ] **SMK-W2-19-3** (Hardware) A forced GPU failure falls back to CPU and still returns text
  - Setup: as SMK-W2-19-2, with a fresh `FP_DD`.
  - Steps: 1. Start the engine as in SMK-W2-19-2 with `SCREENPIPE_WHISPER_GPU_FAULT=inference` in its environment. 2. Play the fixture for 20 seconds. 3. `grep -n "whisper" "$FP_DD/engine.log" | grep -i "gpu\|cpu"`. 4. `api '/search?content_type=audio&limit=5'`. 5. Repeat steps 1 to 4 with `SCREENPIPE_WHISPER_GPU_FAULT=state`.
  - Expected: step 3 shows `GPU inference failed (simulated GPU inference failure ...)`, `GPU disabled for the rest of this process`, `CPU state installed` and `CPU inference finished after GPU recovery`, in that order; step 4 returns the text; later chunks run on CPU without new GPU errors. With `state` the log shows `GPU state creation failed ... rebuilding the shared context on CPU` and the text still arrives.
  - Result:
- [ ] **SMK-W2-19-4** (Hardware) Parakeet picks a DirectML adapter, and SCREENPIPE_DIRECTML=0 forces CPU
  - Setup: the engine from SMK-W2-19-1 with the DirectML build of `onnxruntime.dll` next to it or on `ORT_DYLIB_PATH` (from `src-tauri/bundled/runtime/` after `bun scripts/pre_build.js`); Parakeet weights in the Hugging Face cache (start once with `--audio-transcription-engine parakeet` and wait for the download); a fresh `FP_DD` per run.
  - Steps: 1. Start the engine with `--audio-transcription-engine parakeet` and play the fixture for 20 seconds. 2. `grep -n "parakeet" "$FP_DD/engine.log"`. 3. Stop it, set `SCREENPIPE_DIRECTML=0`, start again with a fresh `FP_DD` and repeat steps 1 and 2. 4. Repeat once more with `SCREENPIPE_DIRECTML=1`.
  - Expected: run 1 logs `parakeet: DirectML adapter ordinal <n>: <GPU name> (<n> MiB dedicated video memory, UMA=<bool>)` and transcribes; software adapters (Microsoft Basic Render Driver) appear only as "skips adapter" lines. Run 3 logs `parakeet: SCREENPIPE_DIRECTML explicitly disabled DirectML; using CPU`, shows no DirectML session line, and still transcribes. Run 4 behaves like run 1 and the line ends with `[SCREENPIPE_DIRECTML on]`.
  - Result:
- [ ] **SMK-W2-19-5** (Hardware) DirectML recycling and CPU recovery during a long session
  - Setup: as run 1 of SMK-W2-19-4.
  - Steps: 1. Leave the engine transcribing speech (a podcast through the speakers) for about 30 minutes. 2. `grep -n "DirectML" "$FP_DD/engine.log" | tail -20`.
  - Expected: once the session has run 500 Parakeet inferences, a `recycling DirectML sessions after 500 inferences` line; no growing transcription latency and no crash. If a DirectML error happens, the next lines show the CPU retry and the text still arrives.
  - Result:
- [ ] **SMK-W2-19-6** (Manual) The installer ships the GPU runtime and models, and the app resolves them from the install dir
  - Setup: an NSIS installer built with `bun tauri build --features official-build,directml,redact-onnx-directml,vulkan` after `bun scripts/pre_build.js` with `FREENPIPE_VULKAN_RUNTIME_DIR` set (unpack LunarG's `vulkan-runtime-components.zip` for 1.4.313.0); the installed screenpipe quit.
  - Steps: 1. Install it. 2. `ls "$LOCALAPPDATA/Freenpipe"` (or the install folder you chose) and its `vad/` and `models/pyannote/` folders. 3. Rename `%LOCALAPPDATA%\screenpipe\vad` and `...\screenpipe\models` caches (if they exist) so they cannot be used, start the app with networking disabled, and record for a minute with speech. 4. Read the engine log for `using installed silero vad model` and `using installed segmentation-3.0.onnx model`.
  - Expected: the install root holds `onnxruntime.dll`, `onnxruntime_providers_shared.dll`, `onnxruntime-LICENSE.txt`, `onnxruntime-ThirdPartyNotices.txt`, `vulkan-1.dll`, `VulkanRT-License.txt` and no `DirectML.dll`; `vad/` holds `silero_vad_v5.onnx` and `NOTICE.md`; `models/pyannote/` holds both speaker models and `NOTICE.md`. Offline, the VAD and speaker models load from the install folder (step 4 lines), and speech is transcribed and attributed to speakers. Restore the renamed caches afterwards.
  - Result:
- [ ] **SMK-W2-19-7** (Hardware) A GPU build starts and runs on CPU on a machine without a Vulkan driver
  - Setup: the installer from SMK-W2-19-6, and a Windows VM or PC without a Vulkan-capable driver (Hyper-V or Windows Sandbox with the Basic Display Adapter works); confirm `C:\Windows\System32\vulkan-1.dll` is absent there.
  - Steps: 1. Install and start the app. 2. Record a minute with speech (or play the fixture). 3. Read the engine log for `whisper context` and `parakeet:` lines.
  - Expected: the app starts (no "vulkan-1.dll was not found" dialog); whisper logs `GPU unavailable; using CPU fallback`; Parakeet logs a CPU decision (no qualifying adapter, or `DirectML.dll could not be loaded`); transcripts arrive.
  - Result:
