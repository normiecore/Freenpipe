# W1-05 Windows smoke checks

### W1-05 Licence gating for commercial builds

- [ ] **SMK-W1-05-1** (Runtime) Search with `filter_pii=true` keeps working when an enclave is configured in a default build
  - Setup: release-dev engine built with default features (`cargo build -p screenpipe-engine --profile release-dev`); `source scripts/dev/dev-env.sh smoke`; in the same shell `export SCREENPIPE_PRIVACY_FILTER_ENCLAVE=enclave.example.invalid SCREENPIPE_PRIVACY_FILTER_REPO=example/enclave SCREENPIPE_PRIVACY_FILTER_API_KEY=dummy`.
  - Steps: 1. Start the engine with `record` on `$FP_PORT` and `--data-dir "$FP_DD"`, logging to `$FP_DD/engine.log`; let it capture for a minute with some text on screen that contains an e-mail address. 2. `curl -s -o /dev/null -w "%{http_code}\n" -H "Authorization: Bearer $SCREENPIPE_API_KEY" "http://127.0.0.1:$FP_PORT/search?limit=5&filter_pii=true"`, then the same request without `-o`/`-w` to read the body. 3. `grep -n "filter_pii" "$FP_DD/engine.log"`.
  - Expected: status 200 (not 503); e-mail addresses in the results are replaced by a placeholder; the log has one warning that the enclave `enclave.example.invalid` is configured but unavailable because the build is "not built with enclave support"; no `attestation` errors and no connection attempts to `enclave.example.invalid`.
  - Result:
