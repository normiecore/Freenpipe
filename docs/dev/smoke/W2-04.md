# W2-04 Windows smoke checks

Entries follow the format in [../windows-smoke-checklist.md](../windows-smoke-checklist.md). Run
them on a W2-04 (or later) build in the isolated dev setup: `FP_DD`, port 3035,
`SCREENPIPE_API_KEY`, with the `api` and `sqlq` helpers from PLAN.md section 4. Start the engine
with `target/release-dev/screenpipe.exe record --port $FP_PORT --data-dir "$FP_DD" --disable-telemetry > "$FP_DD/engine.log" 2>&1 &`.

Helpers for the steps below (Git Bash):

```bash
uuid() { python -I -c "import uuid; print(uuid.uuid4())"; }
ago()  { python -I -c "import datetime as d,sys; print((d.datetime.now(d.timezone.utc)-d.timedelta(minutes=float(sys.argv[1]))).isoformat())" "$1"; }
star() { api /starred-sessions -X POST -H 'Content-Type: application/json' -d "{\"id\":\"$1\",\"start\":\"$2\",\"end\":\"$3\",\"hd_requested\":$4,\"revision\":$5}"; }
fpm()  { sqlq "select count(*) from frames where timestamp > strftime('%Y-%m-%dT%H:%M:%S', 'now', '-60 seconds')"; }
```

`ago -3` is three minutes from now. A starred session raises HD only through the capture rate:
compare `fpm` (frames written in the last minute) while you keep the screen changing (scroll a long
page or play a video in a window that is not excluded).

### W2-04 Starred work sessions backend and HD binding

- [ ] **SMK-W2-04-1** (Runtime) The harness acceptance checks against a real engine
  - Setup: engine running as above with a fresh `FP_DD`; speak or play audio for a minute so at least one audio chunk is written (`sqlq "select count(*) from audio_chunks where file_path != ''"` > 0).
  - Steps: 1. `ID=$(uuid); S=$(ago 2); E=$(ago 1); star $ID $S $E false 0`. 2. `star $ID $S $E false 0` again. 3. `star $ID $S $E false 1`, then `star $ID $S $E false 1` once more. 4. `star $(uuid) $(ago 1500) $(ago 0) false 0`. 5. `api "/starred-sessions?start_time=$(ago 10)&end_time=$(ago 0)"`. 6. `sqlq 'select id, start, end, hd_requested, revision from starred_sessions'`.
  - Expected: step 1 returns HTTP 200 with `"revision":1`; step 2 returns HTTP 409 with `current_revision` 1; step 3 first returns `"revision":2`, the repeat returns 409 with `current_revision` 2; step 4 (a 25 h range) returns HTTP 400; step 5 lists the session from step 1 under `data` with `has_audio` true when audio was recorded in that minute (false otherwise) and `pagination.total` 1; step 6 shows one row with `start`/`end` stored in the `2026-…T…:…:….sssZ` shape and revision 2 (API responses show the same instants in local time unless the request adds `timezone=utc`).

- [ ] **SMK-W2-04-2** (Runtime) A starred HD session raises the capture rate until its end, then the rate drops back
  - Setup: as SMK-W2-04-1, one monitor or more, keep the screen changing throughout.
  - Steps: 1. Note `fpm` (baseline). 2. `ID=$(uuid); star $ID $(ago 0.1) $(ago -3) true 0`. 3. `api /capture/hd`. 4. After 60 s note `fpm`. 5. Wait until the session end has passed plus 70 s, then `api /capture/hd` and `fpm`. 6. `grep -i "starred" "$FP_DD/engine.log"`.
  - Expected: step 3 shows `"active":true` with `"session":{"kind":"starred"}` and `remainingSecs` near 180; step 4 is clearly above the baseline (HD drops the capture interval to `hdRecordingIntervalMs`, 100 ms by default); step 5 shows `"active":false` and `fpm` back near the baseline; step 6 has "HD raised for starred session" and, within a second of the session end, "starred session no longer raises HD", plus "high-fps: monitor … dropping/restoring" lines for each monitor.
  - Result:
- [ ] **SMK-W2-04-3** (Hardware) Starred HD honours the screen lock, a per-monitor pause and an excluded window
  - Setup: engine started with `--ignored-windows Notepad`, two monitors, a starred HD session of 10 minutes started as in SMK-W2-04-2 step 2 (`ago -10`).
  - Steps: 1. Lock the PC (Win+L) for 60 s, unlock, then `sqlq "select count(*) from frames where timestamp > strftime('%Y-%m-%dT%H:%M:%S', 'now', '-90 seconds') and timestamp < strftime('%Y-%m-%dT%H:%M:%S', 'now', '-35 seconds')"`. 2. Pause the secondary monitor `N` with `api /vision/device/stop -X POST -H 'Content-Type: application/json' -d '{"monitor_id": N}'`, keep working on it for 60 s, then `sqlq "select device_name, count(*) from frames where timestamp > strftime('%Y-%m-%dT%H:%M:%S', 'now', '-60 seconds') group by device_name"`; resume it with `/vision/device/start`. 3. Focus a Notepad window full-screen on the primary monitor and type in it for 60 s, then `sqlq "select count(*) from frames where app_name like '%Notepad%' and timestamp > strftime('%Y-%m-%dT%H:%M:%S', 'now', '-60 seconds')"`.
  - Expected: step 1 counts no frames from while the screen was locked; step 2 lists no `monitor_N` row while it was paused, the other monitor still at the HD rate; step 3 returns 0. `api /capture/hd` reports the starred session as active throughout (HD is a rate; the capture gates decide whether anything is captured).

- [ ] **SMK-W2-04-4** (Runtime) Ending, editing and switching HD off take effect at once; the tray stop works
  - Setup: engine running; a starred HD session `ID` of 30 minutes (`star $ID $(ago 0.1) $(ago -30) true 0`, revision 1).
  - Steps: 1. `api /capture/hd`. 2. `star $ID <same start> $(ago 0) true 1` (end it now), then `api /capture/hd`. 3. `star $ID <same start> $(ago -20) true 2` (extend it), then `api /capture/hd`. 4. `star $ID <same start> $(ago -20) false 3`, then `api /capture/hd`. 5. `star $ID <same start> $(ago -20) true 4`, then `api /capture/hd/stop -X POST`, wait 20 s, `api /capture/hd`. 6. `star $ID <same start> $(ago -25) true 5`, then `api /capture/hd`.
  - Expected: step 1 active, kind `starred`; step 2 inactive; step 3 active again; step 4 inactive; step 5 inactive after the stop and still inactive 20 s later (the 15 s refresh does not bring it back); step 6 active again (a new save is a fresh request).
