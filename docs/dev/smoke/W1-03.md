### W1-03 Integration seams, stub modules and shared constants

- [ ] **SMK-W1-03-1** (Runtime) The engine serves the same OpenAPI paths and answers through the pass-through layers
  - Setup: release-dev engine built from this commit (`cargo build -p screenpipe-engine --profile release-dev`); `source scripts/dev/dev-env.sh smoke`. For the comparison, a release-dev build of the commit before W1-03 merged (or the count recorded below).
  - Steps: 1. Start the engine with `record` on `$FP_PORT` and `--data-dir "$FP_DD"`, logging to `$FP_DD/engine.log`. 2. `curl -s -H "Authorization: Bearer $SCREENPIPE_API_KEY" http://127.0.0.1:$FP_PORT/openapi.json | python -I -c "import json,sys;print(len(json.load(sys.stdin)['paths']))"`. 3. `curl -s -o /dev/null -w "%{http_code}\n" -H "X-Screenpipe-Client: claude-code" http://127.0.0.1:$FP_PORT/health` and the same `/search?limit=1` request with the bearer token. 4. Stop the engine with Ctrl+C and read the end of `$FP_DD/engine.log`.
  - Expected: the path count equals the pre-W1-03 build's count (78 on the Linux check of this commit); `/health` and `/search` return 200; the log ends with `shutdown complete` and has no `background worker` warning.
