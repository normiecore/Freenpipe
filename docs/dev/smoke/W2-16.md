# W2-16 Windows smoke checks

Entries follow the format in [../windows-smoke-checklist.md](../windows-smoke-checklist.md). Run
them on a W2-16 (or later) build in the isolated dev setup: `FP_DD`, port 3035,
`SCREENPIPE_API_KEY`. `api` and `sqlq` are the helpers from PLAN.md section 4.

### W2-16 Speakers v2: samples, search paging, merge integrity, reassign v2

- [ ] **SMK-W2-16-1** (Runtime) Voice-sample route serves a WAV clip of a recorded chunk
  - Setup: release-dev engine on `$FP_PORT` with a fresh `FP_DD`; record about two minutes with a microphone while speaking.
  - Steps: 1. `sqlq "select id, file_path from audio_chunks order by id desc limit 1"` and note the id. 2. `api '/speakers/sample/<id>?start=0&end=2' -D - -o "$FP_DD/clip.wav"` (headers print, the body goes to the file). 3. Play `clip.wav`. 4. `api '/speakers/sample/<id>?start=2&end=2' -i`. 5. `api '/speakers/sample/999999?start=0&end=1' -i`. 6. `curl -s -i "http://127.0.0.1:$FP_PORT/speakers/sample/<id>?start=0&end=1&token=$SCREENPIPE_API_KEY"`.
  - Expected: step 2 is `200` with `Content-Type: audio/wav` and `Cache-Control: private, max-age=3600`; step 3 plays two seconds of your voice; step 4 is `400`; step 5 is `404` with `{"error":"audio chunk not found"}`; step 6 (token in the query, no header) is `200`.
  - Result:
- [ ] **SMK-W2-16-2** (UI smoke) Speaker settings play samples through the engine
  - Setup: dev app (`scripts/dev/app-dev.sh`) against the engine above, after it has created at least one unnamed speaker.
  - Steps: 1. Open Settings, Speakers. 2. Press play on an unnamed speaker's inline preview and on a sample in its expanded view. 3. Open the webview devtools Network tab and repeat.
  - Expected: each play button plays the right voice for up to the shown duration and then stops; the Network tab shows `GET /speakers/sample/<id>?start=…&end=…&token=…` returning `audio/wav`, with no `asset://` or file URL requests for the clip.
  - Result:
- [ ] **SMK-W2-16-3** (Runtime) Autocomplete search pages names without samples
  - Setup: engine above with at least six named speakers starting with "a" (name them through the UI or `api '/speakers/update' -X POST -H 'Content-Type: application/json' -d '{"id":<id>,"name":"Ann"}'`).
  - Steps: 1. `api '/speakers/search?name=a&limit=5&include_samples=false'`. 2. `api '/speakers/search?name=A&limit=5&offset=5&include_samples=false'`. 3. `api '/speakers/search?name=a'`.
  - Expected: step 1 returns at most 5 entries, ordered by name ignoring case, each with `"metadata":"{}"`; step 2 returns the rest; step 3 returns metadata with `audio_samples` whose items carry `audio_chunk_id` and never an empty, `.` or `cloud://` path.
  - Result:
- [ ] **SMK-W2-16-4** (Runtime) Reassign `scope:"auto"` names a whole voice and undo restores it
  - Setup: engine above with an unnamed speaker that has transcriptions in at least two chunks (`api '/speakers/unnamed?limit=5&offset=0'`, note a speaker id and one `audio_chunk_id` from its samples).
  - Steps: 1. `api '/speakers/reassign' -X POST -H 'Content-Type: application/json' -d '{"audio_chunk_id":<chunk>,"new_speaker_name":"Smoke Tester","propagate_similar":true,"scope":"auto"}'`. 2. `sqlq "select name from speakers where id = <speaker>"`. 3. Undo: `api '/speakers/update' -X POST -H 'Content-Type: application/json' -d '{"id":<speaker>,"name":""}'`. 4. Repeat step 1 with `"scope":"chunk"` and a new name, then post the returned `old_assignments` and `old_segment_assignments` to `/speakers/undo-reassign`.
  - Expected: step 1 returns `renamed_whole_speaker: true`, `previous_speaker_name: ""`, `new_speaker_id` equal to the speaker id and empty `old_assignments`; step 2 prints the new name; after step 3 the speaker is unnamed again; step 4's reassign moves only that chunk (`renamed_whole_speaker: false`) and the undo answers `{"restored": n}` with the chunk back on its old speaker.
  - Result:
- [ ] **SMK-W2-16-5** (Manual) Automatic self-naming waits for clean microphone evidence
  - Setup: Settings user name filled in; fresh `FP_DD`; engine restarted after setting the name; no meeting running.
  - Steps: 1. Talk alone into the microphone, in sentences longer than two seconds, for about three minutes (three or more 30 s chunks). 2. Wait three minutes. 3. `sqlq "select id, name from speakers"`. 4. Repeat with a second person also talking into the same microphone in a fresh `FP_DD`.
  - Expected: in the first run, `engine.log` reports the dominant input speaker being named after the user and step 3 shows the user name on that speaker; in the second run (two voices on the microphone) no speaker is named automatically.
