# Cloud environment: one-time owner setup

These steps prepare Claude Code cloud sessions to build Freenpipe, so the WORKER and MERGER routines
([cloud-routines.md](cloud-routines.md)) can run while your PC is off. Do them once. The sessions
themselves follow [cloud-runbook.md](cloud-runbook.md).

## 1. Give Claude access to the repository

1. Open <https://github.com/apps/claude> and choose **Configure** (or **Install**).
2. Pick the `normiecore` account, select **Only select repositories**, add **normiecore/Freenpipe**, and
   save.
3. At <https://claude.ai/code>, finish onboarding if it asks you to connect GitHub.

The app lets sessions clone the repository, push branches and call the GitHub REST API through
Anthropic's GitHub proxy, and it enables GitHub event triggers for routines. Your GitHub token never
enters the VM. Everything a routine does on GitHub (claims, PRs, comments, merges) appears under
your GitHub account.

Check two repository settings on GitHub:

- **Actions are enabled** (Settings > Actions > General). Freenpipe CI, Secret Scan and the Windows CLI
  Integration Test form the merge gate ([ci.md](ci.md)).
- **No rule stops your account from pushing to `main`**. The merger pushes `status:` commits there and
  merges PRs through the API. If you add branch protection or a ruleset later, let your own account
  bypass it, or `fp.py publish-status` fails.

## 2. Create the cloud environment

At <https://claude.ai/code>, open the environment selector under the message box, choose
**New environment**, and fill in the dialog:

### Name

`freenpipe`

### Network access

Choose **Custom**, tick **Also include default list of common package managers**, and enter these
allowed domains:

```text
cdn.pyke.io
*.blob.core.windows.net
```

Why each one is there, checked against the code:

| Host | Needed by | Without it |
|---|---|---|
| `cdn.pyke.io` | The `ort` crate (2.0.0-rc.10, feature `download-binaries`) downloads ONNX Runtime 1.22 from it at **build time** on Linux, for `screenpipe-audio` and `screenpipe-redact`. | `bootstrap.sh` falls back to the official ONNX Runtime GitHub release and links it dynamically. Builds work, but differ from CI. |
| `*.blob.core.windows.net` | GitHub Actions job logs. The logs API (`fp.py log`) redirects to Azure blob storage. | Workers see only the failed step names and annotations (`fp.py ci --why`), which is often not enough to fix a Windows compile error. |

Optional:

| Host | Needed by |
|---|---|
| `huggingface.co`, `*.huggingface.co`, `*.hf.co` | Only the `#[ignore]`d model tests in `crates/screenpipe-audio/tests` (Whisper, Silero VAD, embedding models) and the PII model downloads in `screenpipe-redact`. The default test suite and CI do not download models. Add these only if you want workers to run those tests by hand. |

Already covered by the default list (nothing to add): GitHub, including release assets, raw files and
codeload; `crates.io`, `index.crates.io` and `static.crates.io`; `static.rust-lang.org`;
`registry.npmjs.org`; the Ubuntu archives; PyPI; and `fonts.googleapis.com` and `fonts.gstatic.com`,
which `next/font` fetches during `bun run build`.

Not needed: `gyan.dev` (Windows-only, and `pre_build.js` already uses the GyanD GitHub mirror) and
`johnvansickle.com` (the Linux static ffmpeg; the VM links the apt `ffmpeg` instead).

### Environment variables

```text
BASH_DEFAULT_TIMEOUT_MS=600000
BASH_MAX_TIMEOUT_MS=3600000
```

These let a foreground command run 10 minutes by default and up to an hour on request, which suits
Rust builds. Add no tokens or secrets. The GitHub proxy authenticates `gh` and `git` (`GH_TOKEN` reads
`proxy-injected` inside sessions), and nothing else needs a key.

### Setup script

Paste the script below. It runs as root on Ubuntu 24.04 before Claude Code starts. It installs the
system packages for the Rust workspace and the Tauri app, plus the Rust toolchain pinned by
`rust-toolchain.toml` (1.94.1 with every listed target). The apt install and the Rust install run in
parallel, which typically keeps the script under the roughly five-minute limit for the environment
cache. Once it is cached, new sessions start from the snapshot and skip it. The script always exits 0.
Anything that did not finish is repeated by `tools/cloud/bootstrap.sh` in the session.

<!-- BEGIN SETUP SCRIPT (generated: bash tools/cloud/bootstrap.sh --print-setup-script) -->
```bash
#!/bin/bash
# Freenpipe cloud environment setup (runs as root on Ubuntu 24.04, before Claude Code starts).
# Generated by: bash tools/cloud/bootstrap.sh --print-setup-script
# Keep it under ~5 minutes so the environment snapshot is cached. It never fails the session:
# tools/cloud/bootstrap.sh repeats any step that did not complete here.
export DEBIAN_FRONTEND=noninteractive

install_apt() {
  apt-get update -qq || return 1
  apt-get install -y -qq --no-install-recommends \
    build-essential g++ cmake clang libclang-dev pkg-config curl ca-certificates xz-utils \
    unzip xvfb ffmpeg libavformat-dev libavfilter-dev libavdevice-dev libavutil-dev \
    tesseract-ocr libtesseract-dev libssl-dev libsqlite3-dev libbz2-dev zlib1g-dev \
    libonig-dev libxdo-dev libsdl2-dev libxtst-dev libx11-dev libxext-dev libxrandr-dev \
    libxinerama-dev libxcursor-dev libxi-dev libgl1-mesa-dev libasound2-dev libpulse-dev \
    libpipewire-0.3-dev libdbus-1-dev libsamplerate-dev libwebrtc-audio-processing-dev \
    libopenblas-dev libglib2.0-dev libgtk-3-dev librsvg2-dev libwebkit2gtk-4.1-dev \
    libayatana-appindicator3-dev libsecret-1-dev || return 1
  # antirez-asr-sys links "-llibopenblas" (double lib prefix); give the linker that name.
  mkdir -p /usr/lib/x86_64-linux-gnu/openblas/lib
  ln -sf /usr/lib/x86_64-linux-gnu/libopenblas.so /usr/lib/x86_64-linux-gnu/openblas/lib/liblibopenblas.so
  ln -sf /usr/lib/x86_64-linux-gnu/libopenblas.a /usr/lib/x86_64-linux-gnu/openblas/lib/liblibopenblas.a
  if [ -d /usr/include/x86_64-linux-gnu/openblas-pthread ]; then
    ln -sfn /usr/include/x86_64-linux-gnu/openblas-pthread /usr/lib/x86_64-linux-gnu/openblas/include
  fi
}

install_rust() {
  # Toolchain, components and targets exactly as rust-toolchain.toml pins them, so no session
  # downloads them again. rustup-init comes from static.rust-lang.org (on the Trusted list).
  export PATH="$HOME/.cargo/bin:$PATH"
  if ! command -v rustup >/dev/null 2>&1; then
    curl -fsSL -o /tmp/rustup-init https://static.rust-lang.org/rustup/dist/x86_64-unknown-linux-gnu/rustup-init &&
      chmod +x /tmp/rustup-init && /tmp/rustup-init -y --profile minimal --default-toolchain none || return 1
  fi
  rustup toolchain install 1.94.1 --profile minimal -c rustfmt -c clippy \
    -t aarch64-apple-darwin -t x86_64-apple-darwin -t x86_64-pc-windows-msvc -t x86_64-unknown-linux-gnu
}

install_apt > /tmp/fp-setup-apt.log 2>&1 &
apt_pid=$!
install_rust > /tmp/fp-setup-rust.log 2>&1 || echo "rust toolchain install failed (bootstrap.sh retries)"
wait $apt_pid || { echo "apt install failed (bootstrap.sh retries)"; tail -n 20 /tmp/fp-setup-apt.log; }
exit 0
```
<!-- END SETUP SCRIPT -->

Notes:

- `libopenblas-dev` plus the `liblibopenblas` links: `antirez-asr-sys` (the qwen3-asr engine, a default
  feature of `screenpipe-engine`) links `-llibopenblas` with a doubled prefix. CI's linux job uses the
  same links, and `OPENBLAS_PATH` points at them (bootstrap exports it).
- The script installs no `bun` and runs no `bun install` or `cargo fetch`. Those need the repository
  checkout, so `bootstrap.sh` runs them in each session. Bun has known problems with the cloud proxy.
  If `bun install` fails there, frontend build and tests run only in CI.
- To change the package list, edit `FP_APT_PACKAGES` in `tools/cloud/bootstrap.sh`, regenerate this
  block with `bash tools/cloud/bootstrap.sh --print-setup-script`, and paste the new script into the
  environment. Changing the script or the allowed domains rebuilds the cache. The cache also expires
  after about seven days, and the script then runs again.

## 3. Check the environment

Start a session at <https://claude.ai/code> on **normiecore/Freenpipe** with the `freenpipe`
environment and this prompt:

```text
Check the cloud setup for Freenpipe; do not change any files. Run `bash tools/cloud/bootstrap.sh --fetch`
with a 600000 ms timeout (re-run it once if it times out), then `python3 tools/plan/status.py`,
`python3 tools/cloud/test_cloud_tools.py` and `python3 tools/cloud/fp.py ci --main`. Then run
`. ~/.freenpipe-env.sh && cargo check -p screenpipe-db` in the background and wait for it. Report every
bootstrap warning, the ort mode it printed, whether bun install worked, the status summary, the test
results and the cargo result.
```

What to look for:

- No *missing apt packages* warning. If it appears, the setup script did not finish: open the setup
  log in the session (`/tmp/fp-setup-apt.log`) or shorten the package list.
- `ort=download` (with `cdn.pyke.io` allowed) or `ort=github` (fallback).
- `bun install done`. A bun failure is tolerable, because CI covers the frontend.
- The self-test passes, and `status.py` prints the board.
- `cargo check -p screenpipe-db` finishes.

Then create the routines: [cloud-routines.md](cloud-routines.md).
